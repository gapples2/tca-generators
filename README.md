# TCA Generators

A small repository for useful scripts for TCA.

This repository has three main workflows:

- XC function generation from the root scripts (`limited_use.js` and supporting modules)
- Tree grid color extraction from a Tree grid image (`./tree_extract`)
- Tree's gwa minigame "solution" generation (`./tree_gwa_gen`)

The Node-based root generator reads a file containing a manual spreadsheet export from the Apparatus Progress `Function List` tab, filters out unavailable or corrupted functions, and searches for valid solution expressions within the configured limits. The `tree_*` folders contain browser-based helper tools for the other two workflows.

## Overview

This project contains three main workflows, each with a different entry point:

1. XC solution generation at `limited_use.js`
2. Tree grid color extraction using the browser helper at `./tree_extract/index.html`
3. Tree gwa minigame solution generation using the browser helper at `./tree_gwa_gen/index.html`

## Quick start

### XC solution generation

Prerequisites:

- Node.js installed

Instructions:

1. Create a file named `func_list.txt` in the project root.
2. Paste spreadsheet columns B-G from the Apparatus Progress `Function List` tab into that file.
3. Run the generator script from the project root:

```bash
node limited_use.js
```

This generates solutions based on the currently available functions.

To generate the reduced/minimal list when restores or alternative options are available:

```bash
node limited_use.js min
```

4. Review the output in `generated.txt`.

### Tree grid extraction

Open the helper page in a browser:

```bash
./tree_extract/index.html
```

This tool helps extract relevant colors or values from a Tree grid image.

### Tree gwa generator

Open the helper page in a browser:

```bash
./tree_gwa_gen/index.html
```

This tool helps generate candidate solutions for the Tree gwa minigame.

| [func_list.txt](func_list.txt) | Input export from the spreadsheet. This file is not included in the repository template and must be created locally. |

| [tree_extract/script.js](tree_extract/script.js) | Supporting script for the tree extraction helper. |

## File dependency summary

The dependency structure is straightforward:

- [limited_use.js](limited_use.js) is the orchestrator. It imports the configuration and function definitions, then runs the search logic.
- [const.js](const.js) provides the numerical limits and global constants used by the generator and by [unary.js](unary.js) and [binary.js](binary.js).
- [func_info.js](func_info.js) reads [func_list.txt](func_list.txt) and exports the metadata used to decide which functions are available or invalid.
- [const_funcs.js](const_funcs.js) depends on the `unlocked` data from [func_info.js](func_info.js) to filter valid numeric values and names.
- [unary.js](unary.js) and [binary.js](binary.js) define the operation sets used by the search.
- [identity_funcs.js](identity_funcs.js) also depends on the same function metadata and is used when building output expressions and additional identity steps.
- [limited_use.js](limited_use.js) writes the final output to [generated.txt](generated.txt), but the output is not used as an input by the generator itself.

In short, the main chain is:

`func_list.txt` -> `func_info.js` -> `const_funcs.js` + `unary.js` + `binary.js` + `identity_funcs.js` -> `limited_use.js` -> `generated.txt`
